    MODULE 2 | MODERNIZE

    MODERNIZING OPM RPG TO FREE-FORMAT ILE

    i. From understanding to transformation

    In the previous Analyze module, you used IBM Bob to examine and understand the FLIGHT400 application. Bob wrote its own AGENTS member for the library and scanned the application into the Understand Dashboard. It then extracted business rules from FRS401, generated an architecture overview and produced an entity relationship diagram.

    Module 1 established what the application does and how its programs and files relate to one another. This section changes one of those programs.

    Throughout this section, you will use IBM Bob to modernize the OPM RPG program FRS409, the Order Modification Confirmation Window. You will first ask Bob to explain what the program does, then run the RPG Modernization workflow to convert it into free-format ILE RPG, compile it and produce a modernization summary report.

    ii. Why this matters

    A fixed-to-free conversion can change a program's behavior without changing its apparent purpose.

    Successfully converting fixed-format OPM RPG to free-format ILE requires more than translating syntax. Practitioners must:

    • Preserve business rules encoded in indicators, subroutines and workstation data structures
    • Maintain the exact behavior of DOUEQ / CASEQ dispatch loops
    • Convert fixed-column positioning to free-format equivalents without changing semantics
    • Handle the display-file (WORKSTN) and INFDS dependencies correctly
    • Compile the result and validate that the program still behaves identically
    • Produce documentation that explains what changed and why
    TASK WITH: Manual Conversion WITH: IBM Bob Premium Package for i
    Baseline understanding of the program Reading the fixed-format source line by line A plain-language explanation on request
    Fixed-to-free conversion Hours per program, with every MOVE, CAS and TAG rewritten by hand A guided workflow that detects the RPG variant and converts in two phases
    Compile and fix Iterating on compiler listings A compile step with a self-healing loop for compilation errors
    Audit trail Notes kept by the developer, if any A Modernization Summary Report produced with the code

    iii. Modernizing FRS409 with IBM Bob

    The first stage of modernization is understanding the program you are about to transform, then letting the RPG Modernization workflow do the conversion.

    Using IBM i Developer mode and the RPG Modernization workflow, Bob can:

    • Read and explain the original fixed-format OPM RPG source line by line
    • Detect the program type (OPM RPG II or RPG III) automatically
    • Convert fixed-format specifications (F-specs, D-specs and C-specs) to fully free-format RPGLE
    • Remove legacy constructs (TAG, CAS/ENDCS, MOVE, PLIST) and replace them with modern equivalents
    • Compile the modernized source using CRTBNDRPG on your LPAR
    • Produce a Modernization Summary Report documenting every change
    ATTENTION: NON-DETERMINISTIC WORK AHEAD

    Bob's responses are non-deterministic, so the exact analysis, conversion patterns and even compilation messages you see may differ from those shown here.

    IBM Bob is powered by generative AI and LLMs, and a defining trait of these systems is that they are non-deterministic — unlike the deterministic tools most IBM i developers are accustomed to. In practice, the same prompt can produce different free-format code from one run to the next.

    All this is to say: Your results ahead may vary. The key takeaway from this workflow is that you understand how to use the RPG Modernization workflow and review the output it produces. Whether or not you arrive at the exact same RPGLE source is of less importance — Bob will produce a compilable, functionally equivalent program either way. The exact conversion decisions, however, may differ from those documented here.

    iv. Understanding FRS409

    Before modernizing a program, it is good practice to ask Bob what it does. This gives you a baseline to compare against after the conversion, and a sanity check that Bob is reading from the correct source.

    1. In the Object Browser, expand the FLGHT400 filter › qrpgsrc source file, and click frs409.rpg to open the source in the editor.

      Notice the classic fixed-format OPM RPG style: F-specs at the top, indicator definitions, a workstation data structure (WSDS), *ENTRY PLIST with two parameters (ORDER# and ENDYN), and a DOUEQ / CASEQ dispatch loop handling the F3, F12, and Enter keys.

    1. With FRS409.RPG open in the editor, open the Agentic Sidebar chat, click the mode selector at the bottom, and choose IBM i Developer.

      • Click + › New task in Library List so that the task starts clean
      • Check the Permissions menu to confirm that Documentation and Understand are enabled

    1. In the Bob chat prompt, type the following and hit Enter to execute:

      What does this program do?

    1. Bob reads the open source member and returns a complete breakdown of what FRS409 does.

    1. Take a few moments to review Bob's explanation. It should identify:

      • FRS409 is the Order Modification Confirmation Window, an OPM RPG/400 program that displays a pop-up confirmation after a flight ticket order has been modified
      • It receives two parameters: ORDER# (the ticket or order number just modified) and ENDYN (a flag returned to the caller indicating whether the user chose to exit)
      • It displays a FRSWIN record from FRS409DF titled "TICKET CONFIRMATION WINDOW"
      • It handles three keys via a DOUEQ / CASEQ dispatch: Enter (sets ENDYN = 'N', stay in maintenance), F3 (sets ENDYN = 'Y', exit) and F12 (same as F3)
      • It returns control to the calling program with the ENDYN flag set

      This explanation is the baseline you will compare against after the modernization. The converted program must behave identically.

    v. Running the RPG modernization workflow

    With the program understood, the next step is to convert it. You will ask Bob to modernize the program instead of editing the fixed-format source by hand, and Bob will recognize the OPM RPG code and offer the RPG Modernization workflow.

    1. Within the Agentic Sidebar chat, copy & paste the following, then hit Enter to execute:

      Can you modernize this program?

      Bob recognizes the fixed-format OPM RPG code and offers to run the RPG Modernization workflow:

      "Modernizes RPG source into free-format RPG leveraging best practices for modern RPG, including OPM RPG to ILE free-format conversion and ILE fixed-format to ILE free-format conversion."

      Click Start workflow to continue.

    1. The RPG Modernization workflow opens. A welcome message explains that it will guide you through converting any RPG source (OPM or ILE fixed-format) to full free-format ILE RPG, step by step.

      Click Get Started.

    1. The workflow detects that FRS409.RPG is already open in the editor and prompts: "Active RPG Member Detected — Do you want to start the workflow for FLGHT400/QRPGSRC/FRS409.rpg?"

      Select Yes, use FLGHT400/QRPGSRC/FRS409.rpg and click Continue.

      WHAT HAPPENS NEXT

      At this point, Bob reads the source member, detects it as OPM RPG (RPG II or RPG III) and begins the conversion pipeline. It will:

      1. Convert the OPM RPG to ILE RPGLE format (creating a temporary FRS409_T.RPGLE working copy)
      2. Compile the temporary ILE version using CRTBNDRPG to verify the intermediate result
      3. Read and analyze the compiled ILE source
      4. Convert it to fully free-format RPGLE
      5. Compile the free-format version
      6. Fix any compilation errors (self-healing loop)
      7. Report results via a Modernization Summary Report

      You will be prompted to approve at key decision points: the output location, tool approvals and the final report.

    1. Bob completes the OPM-to-ILE conversion and compiles the temporary FRS409_T.RPGLE successfully. It then prompts "Confirm Output Member Location"; the suggested output is FLGHT400/QRPGLESRC/FRS409.RPGLE.

      Select Use suggested location and click Continue.

    1. Bob analyzes the intermediate source file and generates a detailed conversion plan presented as a Todo List. Review the proposed plan carefully to ensure it aligns with your intended modernization approach.

      Once the plan has been reviewed, click Approve todo tools for task. Bob will begin executing the conversion workflow. During implementation, Bob may request approval before performing certain actions such as writing files, running compile commands or fixing errors.

      Review these requests and approve them as needed to allow Bob to continue.

    SEQUENCING THE SUB-TASKS

    In the steps ahead, you will examine in detail what each Sub-Task is performing and understand the rationale for the change. With your approval, Bob will then go ahead and implement the work on your behalf.

    Bob will generate a Todo List with the following (or similar) sub-tasks:

    TASK OBJECTIVE
    Sub-Task 1 Read and analyze the source file (FRS409_T.RPGLE)
    Sub-Task 2 Convert the program to free-format and write to FRS409.RPGLE
    Sub-Task 3 Compile the free-format program
    Sub-Task 4 Fix any compilation errors (self-healing loop)
    Sub-Task 5 Report results via Modernization Summary Report

    Sub-Task 1: Read and analyze the source file

    Before writing any free-format code, Bob analyzes the intermediate ILE source (FRS409_T.RPGLE) produced during the OPM-to-ILE conversion. This includes examining the F-spec, D-specs, C-specs, subroutines and the DOUEQ/CASEQ dispatch pattern, to ensure the free-format conversion preserves every behavioral detail.

    1. Within the Bob chat panel, you will be prompted with the following: Ready to implement Sub-Task 1. Shall I go ahead?

      If you agree with the changes, type Yes and press Enter to approve Sub-Task 1 execution.

    1. Continue approving any additional requests related to Sub-Task 1 until the Bob chat panel has reported back with a summary of Sub-Task 1 is done. Here's what has changed.

      • Source File Analysis: Identified program structure, the WORKSTN/INFDS pattern, named constants, the WSDS data structure, entry parameters and four subroutines
      • Conversion Plan: Mapped every fixed-format construct to its free-format equivalent — TAG to structured flow, CAS to IF/ELSEIF, MOVE to EVAL, PLIST to a procedure interface

    Sub-Task 2: Convert to free-format and write to FRS409.RPGLE

    Bob performs the actual fixed-to-free conversion. Every F-spec, D-spec and C-spec is rewritten into fully free-format RPGLE. Legacy constructs are removed and replaced with modern equivalents. The result is written to FLGHT400/QRPGLESRC/FRS409.RPGLE.

    1. Within the Bob chat panel, you will be prompted with the following: Ready to implement Sub-Task 2. Shall I go ahead?

      If you agree with the changes, type Yes and press Enter to approve Sub-Task 2 execution.

    1. Continue approving any additional requests related to Sub-Task 2 until the Bob chat panel has reported back with a summary of Sub-Task 2 is done. Here's what has changed.

      • Fixed-to-Free Conversion: Converted all specifications to fully free-format RPGLE
      • Legacy Constructs Removed: Replaced TAG, CAS/ENDCS, MOVE and PLIST with modern equivalents

    Sub-Task 3: Compile the free-format program

    Bob runs CRTBNDRPG against the newly written FRS409.RPGLE on your LPAR. The compilation output appears in the terminal panel at the bottom of the IDE.

    1. Within the Bob chat panel, you will be prompted with the following: Ready to implement Sub-Task 3. Shall I go ahead?

      If you agree with the changes, type Yes and press Enter to approve Sub-Task 3 execution.

    1. Continue approving any additional requests related to Sub-Task 3 until the Bob chat panel has reported back with a summary of Sub-Task 3 is done. Here's what has changed.

      • Compilation Executed: Ran CRTBNDRPG against FLGHT400/QRPGLESRC/FRS409
      • Result: Program FRS409 placed in library FLGHT400, highest severity 00

    Sub-Task 4: Fix any compilation errors (self-healing loop)

    If Sub-Task 3 produced compilation errors, Bob automatically reads the error messages, corrects the source and recompiles. In most cases with FRS409, the program compiles on the first attempt and this sub-task completes immediately.

    1. Continue approving any additional requests related to Sub-Task 4 until the Bob chat panel has reported back with a summary of Sub-Task 4 is done. Here's what has changed.

      • Self-Healing: No compilation errors detected. No corrections required

    Sub-Task 5: Generate the Modernization Summary Report

    Bob generates an RPG Modernization Summary Report documenting the entire conversion: what was changed, which legacy constructs were removed and whether the result compiles cleanly.

    1. Continue approving any additional requests related to Sub-Task 5 until the Bob chat panel has reported back with the completed report.

      • Summary Report: Generated a complete audit trail covering spec-by-spec conversion details, compilation results and recommendations for follow-up work

    1. At this stage, all five sub-tasks have been completed and validated. Within the Bob chat panel, locate the RPG Modernization Summary Report and review it.

    1. The modernization report appears directly within the Bob chat panel. Take a few moments to review the generated documentation, which includes:

      • The source file, output file, original RPG type (OPM RPG Fixed-Format) and modernization type (Fixed-to-Free Format Conversion)
      • A complete overview of FRS409 as a workstation-interactive module that accepts an order number and an end indicator as parameters, manages screen I/O via FRS409DF and dispatches function key logic via the INFDS key field
      • Details of every specification converted: F-specs, D-specs, C-specs, named constants and indicator definitions
      • Compilation results, including the outcome and severity level

    1. After reviewing the modernization report, verify the result by comparing the original OPM RPG implementation with the generated free-format ILE equivalent.

      • In the Object Browser, check the new FRS409.PGM timestamp via right-click › Detail. It should show today's date
      • At the bottom of the Bob chat panel, click 1 file changed › Show all to see the FRS409.RPGLE diff. This is the new free-format ILE source derived from the old FRS409.RPG OPM program

      KEEP THE REPORT

      The summary report lives only in the chat. If your team will review the conversion later, ask Bob to save it: Write the Modernization Summary Report to /home/ITZUSER/flght400/docs/FRS409-Modernization-Report.md.

    vi. Key takeaways

    • IBM Bob can modernize fixed-format OPM RPG programs to fully free-format ILE RPG while preserving critical business logic: indicators, workstation data structures, DOUEQ/CASEQ dispatch and *ENTRY PLIST parameter passing
    • Large modernization tasks are best performed using the RPG Modernization workflow in IBM i Developer mode. The workflow reads the source and detects the RPG type. It converts OPM to ILE as an intermediate step, then converts to free format, compiles and corrects any compilation errors
    • Always review the generated conversion plan before implementation, to ensure the proposed analysis and conversion patterns align with your expectations
    • Always ask Bob "What does this program do?" before modernizing it. The explanation gives you a baseline to validate the converted output against; if the behavior description changes after modernization, something went wrong
    • Legacy constructs such as TAG, CAS/ENDCS, MOVE and PLIST are removed and replaced with modern equivalents (IF/ELSEIF, EVAL and a procedure interface). The business logic does not change
    • The RPG Modernization Summary Report provides a complete audit trail of the conversion, including spec-by-spec details, compilation results, legacy constructs removed and recommendations for follow-up work
    • Human review remains essential throughout the process. Review the analysis, the conversion plan, the compiled output and the diff before treating the conversion as complete
