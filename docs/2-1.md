## **ii. Why this matters**

A fixed-to-free conversion can change a program's behavior without changing its apparent purpose.

!!! success ""
    **Successfully converting fixed-format OPM RPG to free-format ILE requires more than translating syntax. Practitioners must:**

    - Preserve business rules encoded in indicators, subroutines and workstation data structures
    - Maintain the exact behavior of `DOUEQ` / `CASEQ` dispatch loops
    - Convert fixed-column positioning to free-format equivalents without changing semantics
    - Handle the display-file (`WORKSTN`) and `INFDS` dependencies correctly
    - Compile the result and validate that the program still behaves identically
    - Produce documentation that explains what changed and why

| TASK | WITH: Manual Conversion | WITH: IBM Bob Premium Package for i |
| --- | --- | --- |
| Baseline understanding of the program | Reading the fixed-format source line by line | A plain-language explanation on request |
| Fixed-to-free conversion | Hours per program, with every `MOVE`, `CAS` and `TAG` rewritten by hand | A guided workflow that detects the RPG variant and converts in two phases |
| Compile and fix | Iterating on compiler listings | A compile step with a self-healing loop for compilation errors |
| Audit trail | Notes kept by the developer, if any | A Modernization Summary Report produced with the code |

## **iii. Modernizing FRS409 with IBM Bob**

The first stage of modernization is understanding the program you are about to transform, then letting the RPG Modernization workflow do the conversion.

Using *IBM i Developer* mode and the RPG Modernization workflow, Bob can:

- Read and explain the original fixed-format OPM RPG source line by line
- Detect the program type (OPM RPG II or RPG III) automatically
- Convert fixed-format specifications (F-specs, D-specs and C-specs) to fully free-format RPGLE
- Remove legacy constructs (`TAG`, `CAS/ENDCS`, `MOVE`, `PLIST`) and replace them with modern equivalents
- Compile the modernized source using `CRTBNDRPG` on your LPAR
- Produce a Modernization Summary Report documenting every change

??? warning "ATTENTION: NON-DETERMINISTIC WORK AHEAD"

    Bob's responses are non-deterministic, so the exact analysis, conversion patterns and even compilation messages you see may differ from those shown here.

    IBM Bob is powered by generative AI and LLMs, and a defining trait of these systems is that they are non-deterministic — unlike the deterministic tools most IBM i developers are accustomed to. In practice, the same prompt can produce different free-format code from one run to the next.

    **All this is to say:** Your results ahead may vary. The key takeaway from this workflow is that you understand how to use the RPG Modernization workflow and review the output it produces. Whether or not you arrive at the exact same RPGLE source is of less importance — Bob will produce a compilable, functionally equivalent program either way. The exact conversion decisions, however, may differ from those documented here.

## **vi. Key takeaways**

---

- IBM Bob can modernize fixed-format OPM RPG programs to fully free-format ILE RPG while preserving critical business logic: indicators, workstation data structures, `DOUEQ`/`CASEQ` dispatch and `*ENTRY PLIST` parameter passing
- Large modernization tasks are best performed using the **RPG Modernization** workflow in **IBM i Developer** mode. The workflow reads the source and detects the RPG type. It converts OPM to ILE as an intermediate step, then converts to free format, compiles and corrects any compilation errors
- Always review the generated conversion plan before implementation, to ensure the proposed analysis and conversion patterns align with your expectations
- Always ask Bob *"What does this program do?"* before modernizing it. The explanation gives you a baseline to validate the converted output against; if the behavior description changes after modernization, something went wrong
- Legacy constructs such as `TAG`, `CAS/ENDCS`, `MOVE` and `PLIST` are removed and replaced with modern equivalents (`IF`/`ELSEIF`, `EVAL` and a procedure interface). The business logic does not change
- The RPG Modernization Summary Report provides a complete audit trail of the conversion, including spec-by-spec details, compilation results, legacy constructs removed and recommendations for follow-up work
- Human review remains essential throughout the process. Review the analysis, the conversion plan, the compiled output and the diff before treating the conversion as complete
